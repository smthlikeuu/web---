Регистрация, вход и роли

Таблица пользователей

Создана таблица users: id, name, email, password_hash, role и created_at. Для email установлен UNIQUE, роль по умолчанию — user.

Регистрация — register.php

Форма принимает имя, e-mail, пароль и повтор пароля. Сервер проверяет обязательные поля, формат e-mail, минимальную длину пароля и совпадение паролей. Перед INSERT пароль хешируется функцией password_hash().

$passwordHash = password_hash($password, PASSWORD_DEFAULT);
$stmt = $pdo->prepare(
  'INSERT INTO users (name, email, password_hash)
   VALUES (:name, :email, :password_hash)'
);
$stmt->execute([
  'name' => $name,
  'email' => $email,
  'password_hash' => $passwordHash,
]);

Вход — login.php

Пользователь ищется по e-mail подготовленным SELECT. При успешной password_verify() обновляется id сеанса и в Session записываются user_id, user_name, user_email и role.

if ($user && password_verify($password, $user['password_hash'])) {
    session_regenerate_id(true);
    $_SESSION['user_id'] = (int)$user['id'];
    $_SESSION['user_name'] = $user['name'];
    $_SESSION['user_email'] = $user['email'];
    $_SESSION['role'] = $user['role'];
}

Ограничение доступа

profile.php требует наличия user_id. admin_guard.php проверяет, что role равна admin. Защита подключена к административному index.php, create.php, edit.php и delete.php из прошлой практики. Скрытия ссылки в интерфейсе недостаточно: проверка нужна на сервере.

После изменения роли в phpMyAdmin необходимо выйти и войти снова, так как значение role уже помещено в Session при авторизации.

Каталог и AJAX

Публичный каталог

catalog.php читает товары из products и отображает карточки. Каждая карточка содержит категорию, название, цену, остаток и ссылку на product.php?id=... . Для обычного пользователя в каталоге нет действий редактирования и удаления.

Карточка товара

product.php проверяет id, получает одну запись подготовленным SELECT и показывает подробности. Если id некорректен, возвращается код 400; если товар отсутствует — 404.

JSON API — api/product.php

API принимает id, валидирует его, выполняет параметризованный запрос и возвращает JSON с id, price и stock. При ошибке формируется JSON-ответ с описанием и соответствующим HTTP-кодом.

echo json_encode([
  'ok' => true,
  'product' => [
    'id' => (int)$product['id'],
    'price' => (float)$product['price'],
    'stock' => (int)$product['stock'],
  ],
], JSON_UNESCAPED_UNICODE);

Обновление в браузере

Кнопка на product.php запускает fetch(). JavaScript читает JSON и обновляет текст цены и остатка в DOM. Страница при этом не перезагружается.

Нажатие → fetch(api/product.php?id=...) → JSON → обновление цены и остатка

Самостоятельная часть

Создана страница my-data.php: показывает приветствие, роль пользователя и разные ссылки для user и admin. Значения Session при выводе проходят через htmlspecialchars().

Вывод

В ходе практической работы подготовлены регистрация и авторизация DemoShop с безопасным хешированием паролей, Session и ролями user/admin. Созданы публичный каталог и отдельная карточка товара. Через AJAX-запрос к JSON API реализовано обновление актуальных цены и остатка без полной перезагрузки страницы.

Закреплены навыки подготовленных запросов PDO, проверки доступа на сервере, формирования JSON и разделения публичной и административной частей приложения.

Перед сдачей: на локальном OpenServer выполните тест регистрации, входа, роли admin, каталога, API и AJAX; добавьте скриншоты phpMyAdmin и браузера. Запуск к базе в текущей среде не выполнялся. Реальный пароль на скриншоты не включайте.

Краткие ответы для защиты

password_hash() создает хеш; password_verify() проверяет введенный пароль; Session хранит состояние входа; fetch() отправляет фоновый запрос; JSON передает структурированные данные API.
