Цель и план эксперимента

Цель работы

Научиться измерять сетевую загрузку страницы через DevTools Network, находить ресурсы и запросы, влияющие на производительность, выполнять оптимизации и сравнивать результаты до и после.

Стенд DemoShop

Созданы две сопоставимые версии одной учебной страницы. Версия slow.php намеренно использует многомегабайтные BMP, несколько CSS/JS-файлов и три последовательных API-запроса. Версия fast.php заменяет тяжёлые изображения, сокращает количество файлов и объединяет данные в один JSON-запрос.

slow.php → измерение Network → оптимизация → fast.php → повторное измерение

Измерение до оптимизации

Как фиксировался результат

В DevTools открывается Network, очищается список запросов и выполняется перезагрузка страницы. Для отдельного измерения кэша используется Disable cache, для проверки кэша — флажок снимается.

Проверяются количество ресурсов, их тип, размер переданных данных, Waterfall и последовательность API-запросов. Измерения выполняются на одном компьютере и в одинаковых условиях.

Фактические значения нужно вписать после локального запуска. В этой среде OpenServer/браузер не запускались, поэтому несуществующие скриншоты и измерения не подменялись макетами.

Ожидаемый результат стенда

На первом экране fast.php имеет меньше запросов, чем slow.php. Нижний промо-ресурс при загрузке страницы не сразу запрашивается благодаря lazy loading. Объём изображений значительно уменьшается. Вместо трёх последовательных API-обращений остается одно.

Важно о кэше: public-кэширование допустимо здесь только потому, что API выдаёт одинаковые учебные данные всем. Его нельзя копировать на личные кабинеты, данные сессий и персональные ответы.

Вывод

В учебном стенде производительность сравнивается измеряемо, а не визуально: учитываются типы и количество ресурсов, размеры файлов, Waterfall, задержка API и заголовки кэширования. Основной эффект дают уменьшение объёма изображений и устранение последовательных запросов. Изменения считаются успешными только при сохранении функциональности страницы.

В приложение к отчету добавьте фактические скриншоты slow.php и fast.php, Network до/после и заголовок Cache-Control из вашего браузера. Не выдавайте ожидаемые цифры стенда за измерения вашего компьютера.
